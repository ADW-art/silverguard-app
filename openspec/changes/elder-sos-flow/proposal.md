## Why

老人端目前只有设计稿，没有可运行工程，无法验证长按防误触、状态反馈和异常替代动作。主动求助是比赛演示与真实使用中优先级最高的链路，应先形成可独立运行、可测试的老人端切片，再接入家属端和服务端。

## What Changes

- 建立全新的 uni-app + Vue 3 + TypeScript 老人端工程基础、暖金主题 tokens 和基础组件。
- 实现老人端首页，以及“长按求助 → 3 秒确认 → 已发送 → 等待家属 → 已接管/无人响应”的本地演示状态机。
- 在倒计时结束前允许松手取消；活跃求助期间合并重复触发，避免产生多个事件。
- 为已接管和无人响应提供明确反馈与可执行的联系入口。
- 使用本地模拟网关隔离页面与未来 REST/WebSocket 实现，保证首个切片不依赖未完成的服务端和家属端。
- 保留 Android 真机验收入口与后续接口替换点。

非目标：本 change 不实现家属端、真实通知、数据库持久化、后台风险判断、定位、系统电话拨号、AI 对话或真实养老控制台对接。

## Capabilities

### New Capabilities

- `elder-sos`: 老人端主动求助的防误触触发、等待、接管、无人响应、重复触发和恢复规则。

### Modified Capabilities

无。

## Impact

- 新增 `app/` 下的 uni-app 前端工程、老人端页面、组件、状态模型和模拟求助网关。
- 当前无服务端数据变更；模拟事件只存在于前端运行期，重新启动后清空。
- 未来真实接口应保持同一领域状态，不允许 AI 直接决定风险等级或阻塞求助链路。
- 验收证据包括 TypeScript/构建检查、状态模型自动化测试，以及后续 Android 真机的长按、取消、安全区与返回行为记录。
