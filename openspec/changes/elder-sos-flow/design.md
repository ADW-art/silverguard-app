## Context

参见 `proposal.md`。当前 `app/` 没有 uni-app 工程，老人端只有 Figma 设计和 UX 规格。首个实现需要先验证移动端交互与状态组织，同时避免把尚未确定的服务端协议写死在页面中。

## Goals / Non-Goals

**Goals:**

- 建立可由 HBuilderX 或命令行运行的 uni-app + Vue 3 + TypeScript 基线。
- 以纯状态模型表达求助生命周期，并由 Vue composable 负责计时和页面导航。
- 使用统一 `SosGateway` 接口隔离本地模拟与未来 REST/WebSocket 实现。
- 将老人端视觉 tokens 和可复用组件放在独立目录，为后续用药、联系人和生活工具复用。
- 使长按取消、重复触发、接管和无人响应能够自动化验证。

**Non-Goals:**

- 本 change 不建立 Prisma 表、服务端告警状态机或真实家庭通知。
- 本 change 不调用系统电话、定位、推送、AI 或养老总控制台。
- 本 change 不实现家属端界面，也不修改当前 Figma 视觉方案。

## Decisions

### 使用 Vue 3 Composition API 与独立领域状态机

页面只渲染状态并转发用户动作；`sosMachine` 负责合法状态转换。与把多个布尔值直接写在页面相比，这能避免“已接管同时又显示无人响应”等矛盾状态，并能在不启动真机的情况下测试。

### 长按由指针事件与单调计时共同判断

按钮监听 touch/mouse 对应事件并记录开始时间，以固定间隔刷新可视倒计时；是否满 3 秒以实际经过时间判断，不依赖 interval 调用次数。页面隐藏或组件卸载时统一清理定时器，防止后台误触发。

### 网关返回事件流，模拟实现只用于开发

`SosGateway` 暴露创建求助和订阅状态的方法。`createMockSosGateway` 使用可注入时长驱动“已通知 → 已接管/无人响应”；后续真实实现可改用 REST 创建事件和 WebSocket/SSE 订阅，页面与状态机不变。

### 首个切片采用单页状态呈现

首页显示常态，触发后使用全屏求助状态层承载倒计时、等待和结果，减少原型阶段的路由复杂度。底部导航在求助状态层隐藏，返回行为由当前状态决定。后续如果交互验收要求独立路由，可保持同一状态模型拆页。

### 模拟模式标识只进入开发说明

核心老人界面不出现工程术语。首页底部开发说明标记“演示模式不会发送真实通知”，生产构建可通过配置关闭；比赛演示接入服务端后移除该说明。

## Risks / Trade-offs

- [本地模拟不能证明真实通知成功] → 验收中明确区分状态模型测试与端到端测试，服务端 change 完成后补充真实证据。
- [长按在不同端的事件名称与取消行为不同] → 同时处理 touch cancel、touch end、mouse leave 和页面卸载，并以 Android 真机作为最终证据。
- [单页状态层后续可能需要拆路由] → 状态机和网关不依赖页面结构，拆分不会改变领域契约。
- [定时演示可能让用户误以为真实家属接管] → 开发模式显示模拟说明，接管人使用明确的演示数据源，禁止提交真实个人信息。

## Migration Plan

1. 保留现有 `app/README.md` 中的全新实现约束并补充运行说明。
2. 新增工程基线、状态机、模拟网关与首页。
3. 在命令行完成类型检查、单元测试和 H5 构建。
4. 使用现有 HBuilderX 打开 `app/`，完成 Android 真机长按与安全区验收。
5. 真实服务端就绪后新增网关实现，通过环境配置替换模拟网关；模拟实现继续用于自动化测试和离线演示。
