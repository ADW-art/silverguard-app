## Purpose

定义老人查看今日用药、确认服药和稍后提醒的可观察行为，确保页面只记录计划状态，不提供医疗判断，并为未来接入真实服务端保留稳定的数据边界。

## ADDED Requirements

### Requirement: 今日用药计划

系统 SHALL 向老人展示当天用药计划，并为每条计划显示时间、药品、剂量和当前状态。

#### Scenario: 查看今日计划

- **当** 老人从首页进入今日用药
- **那么** 系统显示今天的计划列表和剩余次数
- **并且** 当前提醒在视觉层级上优先于已完成项目

### Requirement: 确认服药

系统 SHALL 允许老人从提醒详情确认已服药，并立即更新今日计划。

#### Scenario: 首次确认

- **当** 老人对未完成计划点击“确认已服药”
- **那么** 该计划更新为“已完成”
- **并且** 今日剩余次数同步减少

#### Scenario: 重复确认

- **当** 老人再次确认已经完成的计划
- **那么** 系统不得重复写入完成记录
- **并且** 明确提示该次用药已经确认

### Requirement: 稍后提醒

系统 SHALL 允许老人将正在提醒的计划延后，并显示新的提醒时间。

#### Scenario: 延后十分钟

- **当** 老人点击“稍后提醒”
- **那么** 当前计划变为“即将开始”
- **并且** 提醒时间在原时间基础上延后十分钟

### Requirement: 已错过状态

系统 SHALL 以中性、可理解的方式显示已错过计划，且 MUST NOT 生成补服或剂量建议。

#### Scenario: 查看已错过计划

- **当** 今日计划状态为“已错过”
- **那么** 页面显示“已错过”及原计划时间
- **并且** 页面不显示任何医疗判断或自动补服建议

### Requirement: 本地演示边界

系统 SHALL 明确本地用药数据仅用于交互演示，不能让用户误以为已与医生、药房或家属同步。

#### Scenario: 查看演示说明

- **当** 老人进入今日用药或提醒详情
- **那么** 页面显示简短的本地演示标识
- **并且** 不声称已经向外部角色发送结果
