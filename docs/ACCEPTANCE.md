# MVP 验收标准

本文件区分设计交付与可运行功能。设计稿完成不等于对应业务功能已经实现。

## 0. 设计阶段

- [x] 视觉方向、颜色、字号、间距、圆角、风险状态和组件规则已确定。
- [x] 老人端功能边界、信息架构、17 张页面/状态和主要点击路径已形成设计交付。
- [x] 老人端未向用户暴露设备、网络、网关或传感器管理。
- [x] AI 对话仅保留扩展位，V1 老人端没有可见入口。
- [x] 家属端功能边界、信息架构、页面清单和告警处理状态完成确认。
- [ ] 家属端 11 张核心页面/状态和主要点击路径形成设计交付。
- [ ] “老人求助 → 家属收到告警 → 接管处理 → 老人看到结果”的跨角色原型闭环通过评审。
- [ ] 两端关键页面完成适老化、对比度、文案和异常状态专项检查。

## A. 必须可演示

- [ ] 新用户或演示账号能够登录，角色权限有效。
- [ ] 能够建立一个老人和至少一名家属的绑定关系。
- [ ] 模拟器能够产生统一事件，事件能在服务端保存。
- [ ] 规则能够根据事件生成低/中/高风险结果，并显示命中原因。
- [ ] 高风险事件能够进入告警状态并通知家属侧。
- [ ] 家属能够确认接管、标记处理或升级，状态变化可追踪。
- [ ] AI 能为事件生成可读摘要或关怀建议；AI 失败时基础告警仍完成。
- [ ] 用药提醒至少支持计划、确认和漏服提示。
- [ ] App 页面在真实 Android 设备上完成核心流程操作。

## B. 比赛展示需要说明

- [ ] 能用一条完整故事线演示“老人异常 → 规则判断 → 家庭协同 → 处理闭环”。
- [ ] 能解释规则引擎和 AI 的职责边界。
- [ ] 能展示项目相对原有养老平台的创新点和社会价值。
- [ ] 能说明未来与养老总控制台的接口预留位置和适配方式。
- [ ] 能提供架构图、数据流、关键页面截图、测试记录和未完成项。

## C. 质量与安全

- [ ] 接口参数有校验，错误响应可理解。
- [ ] `.env` 和真实个人数据未进入 Git。
- [ ] AI 超时、网络异常、重复事件和未接管告警有明确处理。
- [ ] Android 真机上没有阻塞主流程的崩溃或布局问题。
- [ ] README 中的命令在干净环境或明确前置条件下可复现。
