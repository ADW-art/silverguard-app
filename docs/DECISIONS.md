| 是否复用原项目源码 | 否 | 原项目只作为内容参考，避免旧页面、写死数据和结构限制新设计 |

## UI 设计 Brief（已确定）

本轮视觉基线以用户提供的暖黄色适老服务界面为主要参考，保留大功能入口、低学习成本和明确底部导航；后两张参考图用于提炼柔和景深、局部玻璃表面、精细阴影、告警证据卡和时间线。整体由“平铺色块”升级为“暖金光感 + 清晰实体操作 + 局部玻璃层次”，不复制其品牌、照片、文案或水印。

### 品牌词

- 温暖可信：让老人感到熟悉、安心，避免医疗机构式压迫感。
- 清晰可达：关键任务一眼可见、一步可完成，减少记忆和阅读负担。
- 主动守护：系统主动发现异常并解释原因，用户始终知道下一步。
- 家人协同：老人端强调求助与联系家人，子女端强调确认、静音和升级处理。
- 温润高级：通过香槟金、奶油底色、柔光景深和克制的半透明表面建立品质感，不依赖通用 AI 插画。
- 克制可靠：高级感服务于层级与状态，告警信息和关键动作始终保持实体、高对比表面。
- 自然无痕：界面以守护结果和真实动作说话，除解释来源或责任边界所必需的场景外，不主动强调“AI”。

### Tokens 原则

- **角色主题**：老人端使用香槟金 `#D6A84B`、深金 `#9C6919`、暖象牙背景 `#F8F2E6` 和深墨正文 `#231E17`；子女端使用松针绿 `#22594D`、深松绿 `#133B32` 与浅雾绿背景 `#F0F4F1`。高风险使用深珊瑚红 `#C24E40`，可承载白色按钮文字并保持 4.5:1 以上对比度。两端以暖金作为品牌连接色。
- **语义色**：安全使用绿色，需关注使用琥珀色，紧急/未处理使用珊瑚红；任何状态必须同时配文字或图标，不能只靠颜色区分。
- **排版**：以 8pt 间距网格为基础；正文不小于 17px，页面标题 24–30px，辅助说明不小于 14px；行高约为字号的 1.45–1.6 倍。
- **触控与密度**：可点击区域至少 48×48px；相邻控件至少保留 8px 间距；每屏只保留一个主任务，避免连续堆叠同权重模块。
- **形状与层次**：采用 16–24px 圆角；主视觉、主按钮允许同色系低跨度渐变；背景可使用 1–3 个低透明柔光色团。玻璃表面只用于状态胶囊、辅助信息卡和底部导航，建议白色 70–86% 不透明度、12–18px 背景模糊、1px 高光边和柔和大半径阴影。关键正文和危险操作必须使用稳定实体底色。
- **阴影**：普通浮层使用低黑度、较大模糊的环境阴影；关键卡片可叠加极弱暖色投影。禁止所有卡片使用同一强阴影或黑色硬边。
- **特殊质感**：老人端使用暖金珍珠釉质感，子女端使用雾玉绿陶瓷质感。主视觉和高优先入口同时具备顶部内高光、底部柔和内阴影、环境投影与少量同心光环；页面背景加入极低透明度微颗粒，避免纯色块的扁平感。
- **材质分工**：高优先操作使用触感明显的釉面实体；辅助信息使用高不透明磨砂陶瓷；导航使用玻璃层。一个页面最多出现三种材质层级，避免所有组件都发亮或悬浮。
- **信息密度**：通过更少元素、更大留白和清晰比例建立高级感。一个功能入口默认只保留图标与动作名称；只有会改变用户决定的实时状态才增加第二层文字。
- **图标**：使用统一线性或实心图标集，图标旁必须有文字标签；紧急、电话、药物、定位、告警等图标保持固定含义。

### 组件规则

- **主按钮**：老人端使用香槟金到暖金的低跨度渐变，子女端使用松针绿到深松绿渐变。按钮文案直接描述动作，高度 52–58px；按下时降低高光并轻微收紧阴影，不改变布局尺寸。
- **功能入口**：采用“一个图标 + 一个动作名称”。不在“联系家人”下重复“一键视频”，不在“监护查看”下重复“状态正常”；行为要求应并入主文案，例如把“紧急求助 + 长按 3 秒”合并为“长按求助”。
- **紧急按钮**：采用第三组的高对比、强识别结构，使用珊瑚红作为紧急语义色，配电话/求助图标和“长按 3 秒”或同等明确的误触提示；触发后显示倒计时、取消和已通知对象。
- **告警列表**：采用参考图中的悬浮列表和时间线思路。每条告警包含状态图标、事件名称、发生时间、数据来源、当前处理状态和进入详情的箭头；列表外框可使用高不透明玻璃表面，单条告警保持实体浅色底，未处理项置顶。
- **告警详情**：顶部先给出老人、风险等级和发生时间；中部展示一句状态摘要、单一趋势图和处理时间线。未接管时固定“暂时静音 / 确认接管”，接管后切换为“联系老人 / 完成处理”；通知其他家属和升级处理进入更多操作。
- **状态卡/数据块**：只展示与当前任务相关的 2–4 项数据，使用大数字、单位和更新时间；不要把所有健康指标做成仪表盘。
- **底部导航**：老人端保持“首页 / 生活 / 消息 / 我的”四项；家属端保持“首页 / 告警 / 守护 / 我的”四项，历史记录合并进告警页。老人端的主动守护由后台运行，不设置技术状态页面；家属端设备信息进入二级“守护”页面，不在首页平铺。两端使用同一导航骨架、高不透明玻璃底板和胶囊形当前项。
- **智能摘要**：只有内容能帮助用户决定下一步时才显示，并使用“状态摘要”或“数据提示”等自然产品语言。责任边界用一句上下文说明表达，不单独堆叠“AI 分析”卡片。

### 页面层级

- **老人端首页**：问候与当前守护状态 → 大按钮“紧急求助” → 最近一条用药提醒及确认 → 今日状态简表 → 联系家人 → 底部导航。
- **老人端生活页**：展示今日日程以及手电筒、日历日程、放大镜和大字计算器四项工具；每个工具保持单一任务界面，未来 AI 对话入口“聊一聊”在能力可用后通过功能开关开放。
- **老人端第二页**：采用“用药提醒”作为第二张定稿页。突出当前时间、药品和单一确认动作；今日计划使用三行列表，不增加解释卡片。
- **家属端首页**：守护岛中的老人信息或最高优先级告警 → 抽象守护圆环与整体状态 → 联系老人/今日记录 → 单一活动趋势 → 底部导航。首页不展示设备矩阵和告警列表。
- **守护岛**：正常时显示老人头像、姓名和最近活动；新告警时平滑展开，只保留“查看”主动作；接管后显示处理家属和接管时长。多个告警只显示风险最高的一条并提示剩余数量。
- **双端统一**：共享品牌、图标、圆角、间距、按钮、时间线、风险语义和“守护圆环”母题；老人端使用暖金珍珠釉，家属端使用松针绿雾玉质感，暖金作为连接色。
- **子女端告警详情**：告警标题、老人和风险等级 → 异常前后活动强度折线图 → 两条关键进展 → 确认接管/静音/联系。取消真实环境画面和冗长证据卡。
- **历史记录页**：按日期和事件类型筛选，列表优先；进入详情后查看完整时间线和处理人，不在首页展示复杂图表。

### 适老化规则

- 使用短句和常用词，按钮文案避免专业术语；每个页面先回答“现在是否安全”和“我该按哪里”。
- 重要数字、时间和状态使用大字号并附单位/解释；正文与背景保持高对比，支持系统字体放大和重排。
- 触控目标至少 48×48px，危险操作需要长按或二次确认；不依赖滑动、拖拽、长列表手势完成关键任务。
- 保持固定的返回位置、底部导航和按钮顺序；语音播报、震动或提示音只作为文字信息的补充。
- 告警文案描述“检测到什么、何时发生、来自哪里、下一步怎么做”，不把传感器结果写成疾病判断。
- 网络或 AI 不可用时仍能完成紧急呼叫、查看最近告警和联系家人等关键路径，并给出清楚的失败提示。
- 老人端不展示设备、网络、网关或传感器管理页面；仅在操作受影响时使用结果型提示，并提供可执行的替代动作。
- 同一动作只解释一次；按钮本身应表达动作，不再在按钮下方追加同义小字。

### 禁止项

- 禁止扁平 AI 插画、卡通老人、装饰性人物插图和大面积宣传海报作为核心页面视觉。
- 禁止紫蓝 AI 渐变、彩虹渐变、霓虹外发光和与品牌无关的炫技效果；渐变必须控制在同色系、低跨度并服务于层级。
- 禁止把整页和所有卡片都做成玻璃；禁止在复杂背景上放低透明正文卡，关键文字对比度不得低于 4.5:1。
- 禁止同权重白色浮卡连续堆叠、同权重彩色入口铺满首页、信息密度接近后台仪表盘。
- 禁止“标题 + 同义副标题 + 状态小字”的模板化三层文案；禁止为了填满空间添加无决策价值的说明。
- 禁止机器人、魔法星光、AI 徽章和“AI 为你……”式营销文案进入核心任务页面。
- 禁止在老人端或子女端使用真实室内照片、监控画面、人物照片或摄影背景；数据证据使用抽象图表、状态色和时间线表达。
- 禁止依赖单层纯色矩形、统一投影或同一种玻璃效果铺满页面；特殊质感必须服从操作层级，不能降低文字对比度。
- 禁止用颜色单独表达风险，禁止低对比度浅灰文字、低于 14px 的关键说明和小于 48px 的关键按钮。
- 禁止把 AI 生成内容写成医疗诊断、风险定级或自动处置决定；风险等级必须来自规则引擎，升级动作必须可追溯。
- 禁止未经确认复制参考图中的品牌、文案、人物照片、图标版权资产或水印。
