# 跨角色告警与家庭接管流程 v1

## 1. 目标

本流程统一老人端、家属端、服务端和未来养老总控制台对同一事件的名称、状态和动作，避免两端各自维护无法对应的“消息”。首条演示闭环聚焦老人主动求助，设备告警复用同一状态模型。

## 2. 统一状态

| 状态 | 含义 | 老人端表达 | 家属端表达 |
| --- | --- | --- | --- |
| `OPEN` | 告警已生成，暂无家属接管 | 已通知家人，正在等待 | 待处理 |
| `CLAIMED` | 某位家属已确认负责 | 张女士已接管 | 我已接管 / 张女士已接管 |
| `IN_PROGRESS` | 家属正在联系或安排处理 | 家人正在处理 | 处理中 |
| `RESOLVED` | 已记录处理结果 | 已处理，可联系家人 | 已完成 |
| `ESCALATED` | 已通知更多家属或外部支持 | 已通知更多联系人 | 已升级 |

通知发送状态与告警处理状态分别记录。通知失败不能把告警标记为完成；AI 摘要失败不能改变任何状态。

## 3. 主流程

1. 老人长按求助并完成 3 秒确认。
2. 服务端保存统一事件，规则引擎生成高风险告警，状态为 `OPEN`。
3. 服务端通知所有应接收该类型告警的家属；老人端显示“已通知家人”。
4. 家属通过系统通知或首页守护岛打开告警详情。
5. 第一位家属点击“确认接管”，告警进入 `CLAIMED`，其他家属同步看到接管人。
6. 老人端显示接管家属姓名和“家人正在处理”。
7. 接管家属联系老人、通知其他家属或安排上门，告警进入 `IN_PROGRESS`。
8. 家属选择处理结果并完成告警，状态进入 `RESOLVED`；需要更多支持时进入 `ESCALATED`。
9. 老人端收到处理结果，家属端和控制台保留完整时间线。

## 4. 并发与静音

- 同一告警只能有一位当前接管人；并发接管时以服务端首次成功写入为准，后续家属看到“已由某某接管”。
- 当前接管人可以转交给其他家属，转交动作必须进入时间线。
- 静音是“家属账号 + 告警”的个人通知设置，不改变全局告警状态，也不影响其他家属。
- 高风险告警静音到期且未接管时恢复提醒；设备提醒可以使用更长的免打扰策略。
- 已接管告警仍对其他家属可见，但停止无意义的重复高频提醒。

## 5. 超时与失败

| 情况 | 老人端 | 家属端与服务端 |
| --- | --- | --- |
| 暂时无人接管 | 暂时无人响应，可再次联系或拨打电话 | 按通知策略升级给主要联系人和其他家属 |
| 部分通知失败 | 已通知可达联系人 | 记录每位家属的通知结果并继续其他渠道 |
| 全部通知失败 | 暂时未能通知家人，提供直接电话 | 保留 `OPEN`，进入通知重试和控制台待处理队列 |
| 重复求助 | 已收到求助，无需重复操作 | 合并到当前活跃告警并增加事件记录 |
| AI 摘要失败 | 不展示 AI 内容 | 使用规则命中原因，不阻塞处理 |
| 网络中断 | 显示发送失败和直接电话 | 不把本地操作伪装成服务端成功 |

## 6. 设备告警复用

燃气、烟雾、跌倒、异常开门等安全告警使用同一 `OPEN → CLAIMED → IN_PROGRESS → RESOLVED/ESCALATED` 流程。设备离线、低电量和一般数据中断属于设备提醒，不默认要求家庭接管；当守护能力明显受影响时，由规则引擎升级为需要处理的告警。

## 7. 两端一致性规则

- 事件名称、风险等级、发生时间、地点、接管人和处理结果必须来自同一服务端记录。
- 两端共享同一风险图标和语义色，不能在老人端显示“已处理”而家属端仍显示“待处理”。
- 老人端只显示可理解的处理结果，不展示设备编号、通知渠道或内部失败码。
- 家属端展示必要的设备来源和规则原因，不显示后台协议、Webhook 或运行参数。
- 养老总控制台可以读取和补充处理结果，但不能绕过留痕直接删除历史。

## 8. 首条原型验收路径

E01 老人端首页 → E02 求助倒计时 → E03 求助处理中 → F02 家属端新告警守护岛 → F05 告警详情 → F06 确认接管 → F03 家属端已接管 → E04A 家人已接管 → 家属完成处理 → 老人端显示处理结果。
