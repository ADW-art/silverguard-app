# 家属端 UX 规格 v1

## 1. 产品目标

家属端是家庭守护与告警处理入口，不是养老总控制台。第一版帮助家属快速理解“老人现在是否安全、发生了什么、是否有人处理、我现在该做什么”，同时保留原小程序中设备产生告警、家属确认和静音、历史追溯等核心能力。

首页保持安静、生活化和低密度。设备、历史筛选和技术信息进入二级页面，不能在首页以设备矩阵、数据大屏或后台表格形式集中展示。

## 2. 已确认功能范围

### V1 必须完成

- 同一 App 使用账号角色决定默认入口；老人账号进入老人端，家属账号进入家属端。
- 一名老人可绑定多名家属；首版界面默认聚焦一名老人。
- 首页使用“守护岛”承载老人信息和短小、重要的当前告警。
- 状态总览只显示整体结论、一项活动趋势、联系老人和今日记录。
- 活跃告警按风险和时间排序，支持查看详情、确认接管、暂时静音、联系老人、完成处理和升级处理。
- 告警历史支持按风险、类型、设备和时间筛选；筛选器默认收起，历史不能由普通家属清空。
- 守护设备按房间组织，展示生活化名称、当前状态、最近上报时间、最近事件和通知偏好。
- 今日记录使用时间线整合用药完成、活动、普通设备事件和家庭协同结果。
- 家庭成员显示主要联系人和普通家属，告警接管人及处理进度对家庭成员可见。
- AI 只在告警详情提供一句辅助状态摘要；AI 失败时使用规则命中原因，不影响告警处理。

### 首版设备与事件来源

- 随身求助按钮：老人主动求助，最高处理优先级。
- 活动守护设备：跌倒、长时间未活动、异常离床等事件。
- 燃气与烟雾设备：燃气异常、烟雾异常等环境安全事件。
- 入户门守护设备：异常时段开门、长时间未关门等事件。
- 环境传感器：温湿度异常、数据中断等需关注事件。

### 家属端允许的设备操作

- 查看设备状态、最近数据和关联事件。
- 设置当前家属是否接收某类通知。
- 报告设备问题或联系维护人员。

设备绑定、删除、协议配置、阈值管理、固件升级、Webhook、数据保存周期、广播间隔和系统重启由养老总控制台承担，不进入家属端。

### 暂缓

- 家属自行扫码绑定或删除设备。
- 实时监控画面、真实室内照片和连续位置轨迹。
- 医疗诊断、疾病预测和复杂健康数据大屏。
- 家庭群聊、复杂排班、积分、商城和服务预约。
- App 内视频通话；V1 使用系统电话联系老人或相关联系人。
- 多位老人同时平铺在首页；数据结构保留多老人能力，后续通过头像或独立切换器进入。

## 3. 信息架构

底部导航固定为四项：

1. **首页**：守护岛、整体状态、一项活动趋势、联系老人和今日记录。
2. **告警**：待处理告警、告警详情、接管处理和历史记录。
3. **守护**：老人资料、家庭空间、守护设备、设备详情和通知偏好。
4. **我的**：当前家属、家庭成员、通知方式、隐私授权、帮助和问题反馈。

“守护”使用生活化空间与功能名称，不显示硬件协议、原始设备编号或后台配置项。

## 4. 双端统一设计语言

- 两端共享“银龄智护”品牌、字体、8pt 间距体系、圆角、图标、风险语义、按钮结构、弹窗、时间线和底部导航骨架。
- 老人端以暖象牙与香槟金为主；家属端以中明度雾松绿与松针绿为主，暖金作为品牌连接色。
- 两端共享“守护圆环”母题：老人端围绕求助入口，家属端表达平安、异常和接管状态。
- 同一事件在两端使用完全一致的名称、图标、风险颜色、发生时间和处理人。
- 家属端整屏使用统一的中明度雾松绿画布，不设置顶部渐变分区、异色页面区块或大型装饰光斑。
- 普通内容使用乳白和浅雾绿实体表面，通过明确的色调差、细描边与 3–4% 松针绿环境阴影区分。清透材质只用于守护岛、底部导航和固定操作层，使用 82–90% 白色、约 16px 背景模糊和 6% 环境阴影。
- 不叠加明显内阴影，不连续堆叠透明卡片，不使用强玻璃、霓虹外发光或持续闪烁。
- 页面不使用真实住宅、监控、人物摄影背景或卡通 AI 插画。

## 5. 守护岛组件

“守护岛”是 App 内的状态容器，固定在系统状态栏下方，不遮挡正文，也不复制手机系统灵动岛外形。

| 状态 | 主要内容 | 点击结果 |
| --- | --- | --- |
| 平安 | 老人头像、姓名、“今日平安”、最近活动时间 | 查看今日记录 |
| 需关注 | 事件名称、地点、时间、文字风险标签 | 查看事件详情 |
| 高风险 | 最高风险告警、发生时间、“查看”主动作 | 打开告警详情 |
| 已接管 | 接管家属头像和姓名、事件、接管时长 | 查看处理时间线 |
| 多告警 | 最高风险告警、“另有 N 条” | 打开待处理列表 |

规则：

- 岛内最多一项主动作，不放确认、静音、完成等完整处理按钮。
- 多条事件只展示风险最高且最新的一条，高风险优先于发生时间。
- 新告警到达时容器平滑扩展并轻微弹性反馈；高风险不自动消失，直到被接管或完成。
- App 不在前台时仍依赖系统通知；守护岛负责进入 App 后的持续状态反馈。

## 6. 页面与状态清单

| 编号 | 页面/状态 | 主要任务 | 优先级 |
| --- | --- | --- | --- |
| F01 | 首页·平安 | 快速确认老人整体状态 | P0 |
| F02 | 首页·新告警 | 通过展开的守护岛查看最高优先级事件 | P0 |
| F03 | 首页·已接管 | 确认处理家属和处理时长 | P0 |
| F04 | 待处理告警 | 查看按风险排序的活跃告警 | P0 |
| F05 | 告警详情 | 理解结论、证据和下一动作 | P0 |
| F06 | 确认/静音弹窗 | 接管告警或暂停当前账号的重复提醒 | P0 |
| F07 | 告警历史 | 筛选并追溯已处理事件 | P1 |
| F08 | 今日记录 | 查看用药、活动、设备事件和协同时间线 | P1 |
| F09 | 守护空间 | 按房间查看守护设备与状态 | P1 |

## 7. 关键页面结构

### 7.1 首页

守护岛 → 一句问候与整体状态 → 抽象守护圆环 → “联系老人 / 今日记录”两个快捷动作 → 一张最近 6 小时活动趋势 → 底部导航。

首页不出现设备列表、活跃告警列表、历史筛选、设备数量、在线率或多张同权重指标卡。

### 7.2 告警列表

“待处理 / 历史记录”分段切换。每条待处理告警只显示风险、事件名称、地点或来源、发生时间、接管状态和进入详情的箭头。筛选器通过右上角入口打开底部抽屉。

### 7.3 告警详情

事件结论与风险 → 老人和发生时间 → 当前接管状态 → 一句状态摘要 → 一张事件前后趋势图 → 处理时间线 → 固定底部操作。

未接管时显示“暂时静音 / 确认接管”；接管后显示“联系老人 / 完成处理”。通知其他家属和升级处理进入更多操作。

### 7.4 守护空间

按“卧室、厨房、入户门”等生活空间组织。设备使用“卧室活动守护、厨房燃气守护、入户门守护、随身求助按钮”等名称。列表只显示当前状态、最近上报时间和是否存在关联事件。

### 7.5 今日记录

按时间展示用药确认、活动、普通设备事件和告警处理结果。普通记录不使用高风险视觉，也不自动进入告警列表。

## 8. 告警分层

### 安全告警

老人主动求助、跌倒、燃气或烟雾异常、异常开门等需要家庭接管的事件。进入守护岛和待处理列表，并触发系统通知。

### 设备提醒

设备离线、低电量、数据中断和一般环境异常。默认进入守护页；只有守护能力明显受影响时，才在首页守护岛显示“守护服务需检查”，不得伪装成老人本人的高风险状态。

## 9. 处理规则

- “确认接管”改变所有家属可见的告警状态，并记录接管人和时间；第一位有效接管者生效。
- “暂时静音”只暂停当前家属账号对该告警的重复提醒，不改变风险、接管状态或其他家属的通知。
- 高风险告警只提供 10 分钟和 30 分钟静音，不提供“今日免打扰”。
- 完成处理时必须选择结果：已联系老人且情况正常、已通知其他家属、已安排上门查看、已联系紧急支持或其他情况。
- 拨打紧急电话只发起系统电话，不显示成已经自动通知急救机构。
- 普通家属不能清空告警历史；处理动作和通知结果必须留痕。

## 10. 信息密度与无障碍规则

- `360 × 800` 基准画板；正文不小于 16px，关键状态不小于 18px，点击区域至少 48×48px。
- 首页只保留一个主状态、一张趋势和两个快捷动作。
- 每个列表项最多两级文字信息加一个状态标签；设备编号、规则编号和技术字段进入更深层或完全隐藏。
- 风险必须同时使用文字、图标和颜色；所有图表提供文字结论和更新时间。
- 一项操作只解释一次，按钮下不重复添加同义小字。
- 动效持续时间短且可预测，不使用持续闪烁、自动轮播或依赖拖拽完成关键任务。

## 11. 下一步设计顺序

1. F01–F03 首页及守护岛五种状态。
2. F04–F06 活跃告警、详情和接管/静音弹层。
3. F07–F08 历史记录与今日记录。
4. F09–F10 守护空间与设备详情。
5. F11 家庭成员、通知和隐私设置。
6. 连接“老人求助 → 家属收到告警 → 家属接管 → 老人看到结果”的跨角色原型。
